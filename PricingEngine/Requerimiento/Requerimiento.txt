PRICES — Intelligent Pricing & Sales Decision Engine
Arquitectura General, Modelo Conceptual y Diseño del Sistema
Como Arquitecto Senior e Ingeniero de Datos, presento el diseño completo del proyecto PRICES. La solución prioriza rendimiento set-based sobre T-SQL, desacoplamiento con la API de Mercado Libre, explicabilidad completa de cada decisión y flexibilidad multi-empresa.

ETAPA 1: Arquitectura General del Sistema
El principio rector es la separación de responsabilidades en capas asíncronas. El motor de decisiones no depende de llamadas HTTP vivas; opera de forma determinista y set-based sobre una base de datos SQL Server que actúa como single source of truth.

1.2 Flujo de Procesamiento Interno
Sincronización: Workers externos descargan del API de MELI publicaciones, pedidos y snapshots de competencia, insertándolos en tablas Staging.

Consolidación: Procedimientos ETL/Merge consolidan datos a las tablas relacionales de la empresa correspondiente (EmpresaID, CuentaMLID).

Pre-cálculo de Métricas: Se actualizan las tablas resúmenes de ventas (7, 15, 30, 90 días), velocidad de venta diaria y agregados competitivos.

Ejecución del Motor (spCalcularDecision):

Carga la estrategia activa de la empresa y sus reglas de negocio asociadas ordenadas por prioridad.

Aplica evaluaciones vectorizadas (SET-BASED) en tablas temporales/TVPs.

Aplica filtros duros de seguridad (Límites de margen, Precio Mín/Máx).

Valida reglas de Anti-Oscilación (Cooldown/Histéresis).

Genera la decisión final y su explicación estructurada.

Persistencia / Salida: Si @ModoSimulacion = 0, la decisión se encola en ColaEjecucionML y se audita en HistorialDecisiones. Si @ModoSimulacion = 1, solo se registra en la estructura de simulación/auditoría.

ETAPA 3: Motores de Reglas, Estrategias y Prioridades
El sistema desacopla la lógica de las reglas del código procedural mediante una arquitectura parametrizable por Estrategia y Pesos/Prioridades.

3.1 Estructura de Estrategias y Prioridades
Una Estrategia (ej. AGRESIVA_VOLUMEN, MAXIMO_MARGEN, LIQUIDACION_STOCK) se compone de un conjunto de reglas asociadas con prioridades y parámetros específicos por empresa.

+------+----------------------------+-------------------+---------------------------------------------------------------+---------------------------------------------------------------+
| JER. | NIVEL DE REGLA             | TIPO              | DESCRIPCION                                                    | EJEMPLO DE ACCION EN CONFLICTO                                |
+------+----------------------------+-------------------+---------------------------------------------------------------+---------------------------------------------------------------+
| P1   | Filtro Duro de Seguridad   | HARD_RESTRICTION  | Previene perdidas, infracciones y violaciones de precio       | Anula cualquier intento de bajar precio si viola el Margen     |
|      |                            |                   | minimo/maximo legal o comercial.                              | Minimo.                                                       |
+------+----------------------------+-------------------+---------------------------------------------------------------+---------------------------------------------------------------+
| P2   | Anti-Oscilacion / Cooldown | PROTECTION        | Evita bucles de cambios de precios (guerras de precios)       | Bloquea un cambio si se modifico el precio hace menos de N    |
|      |                            |                   | e histeresis.                                                  | horas.                                                        |
+------+----------------------------+-------------------+---------------------------------------------------------------+---------------------------------------------------------------+
| P3   | Reglas Operativas de Stock | OPERATIONAL       | Protege contra quiebre de stock o liquida exceso.             | Aumenta precio si stock es CRITICO e ignora bajas de           |
|      |                            |                   |                                                               | competencia.                                                  |
+------+----------------------------+-------------------+---------------------------------------------------------------+---------------------------------------------------------------+
| P4   | Reglas de Competitividad   | MARKET            | Optimiza posicion contra competidores directos/relevantes.   | Ajusta precio para igualar/superar competidor relevante.      |
+------+----------------------------+-------------------+---------------------------------------------------------------+---------------------------------------------------------------+
| P5   | Reglas de Oportunidad      | OPPORTUNITY       | Captura margen adicional en ausencia de competencia o alta   | Sube precio si no hay competidores directos o la demanda     |
|      |                            |                   | demanda.                                                       | se acelera.                                                    |
+------+----------------------------+-------------------+---------------------------------------------------------------+---------------------------------------------------------------+

PRIORIDAD DE EJECUCION:
P1 > P2 > P3 > P4 > P5

REGLA GENERAL:
Una regla de mayor prioridad siempre tiene precedencia sobre una
regla de menor prioridad cuando existe conflicto.

ETAPA 4: Sistema de Explicabilidad y Anti-Oscilación
4.1 Sistema de Explicabilidad
Para que cada decisión sea auditable, el motor guarda una traza detallada en formato JSON/Relacional con el desglose de evaluación:

PuntajesEvaluados: Lista de reglas analizadas con sus valores calculados.

ReglasDescartadas: Reglas activadas cuyo resultado fue bloqueado por una regla de mayor prioridad (ej. Margen Mínimo).

ReglaGanadora: Regla que definió la decisión final.

ScoreConfianza: Indicador ponderado (0.00 a 1.00) basado en volumen de datos (cantidad de competidores, estabilidad de ventas).

4.2 Mecanismo Anti-Oscilación (Cooldown e Histéresis)
Para prevenir oscilaciones agresivas de precios causadas por bots competidores:

Cooldown Period: Define un tiempo mínimo configurable (ej. 12 horas) entre cambios de precios para un mismo producto, a menos que la regla sea de tipo EMERGENCY_STOCK.

Histéresis (Threshold de Cambio): No se ejecuta ningún cambio de precio si la variación calculada no supera un umbral mínimo (ej. |PrecioNuevo - PrecioActual| / PrecioActual < 1.5%).

Límite de Variación Máxima por Ejecución: Máximo decremento/incremento permitido por corrida (ej. no cambiar más de un ±5% de una sola vez).

ETAPA 10: Roadmap de Producción
Fase MVP (Semanas 1-4):

Despliegue de scripts DDL e índices en entorno SQL Server.

Conexión del Worker Ingestion API de Mercado Libre hacia las tablas PublicacionesML y StockEstado.

Ejecución programada de spCalcularDecision en Modo Simulación (@ModoSimulacion = 1).

Auditoría diaria de explicabilidad con los usuarios de negocio.

Fase Beta (Semanas 5-6):

Activación del envío en modo producción (@ModoSimulacion = 0) para un subconjunto restringido de SKUs (Piloto del 10% del catálogo).

Monitoreo del mecanismo Anti-Oscilaciones y de los tiempos de la cola ColaEjecucionML.

Fase Producción y Escalamiento (Semanas 7+):

Habilitación de la automatización completa del catálogo.

Activación del módulo de Backtesting continuo para tuning automático de las prioridades de reglas.

Mantenimiento programado de índices de SQL Server para procesamiento por lotes masivos.
